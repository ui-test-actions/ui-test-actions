The hosted test relay carried only encrypted WireGuard UDP datagrams over WebSocket. The action listened on the WireGuard interface, and the client used the private IP and TLS certificate from the session artifact. The relay was temporary infrastructure for two NATed hosted VMs. The Action's private adapter accepts an existing routed private address and does not run that relay. The Tailscale example uses the same adapter. Verification against an actual tailnet requires that tailnet and a scoped enrollment identity.

A canary isolated a Quick Tunnel startup problem on Ubuntu and both macOS images. Cloudflared registered, but the runner's resolver returned NXDOMAIN or an equivalent name error. An external machine fetched the exact response from both macOS canaries while their local probes still failed. At this pin, Windows, macOS and the Mousepad run all logged successful readiness via Cloudflare DNS over HTTPS with normal hostname and certificate verification. Clients still use their normal DNS policy. [Hosted DNS canary](https://github.com/ui-test-actions/ui-test-actions/actions/runs/44792825836) · [Redacted observations](hosted/dns-diagnosis/result.json)

The regression suite ran at the same exact action pin on Ubuntu, Windows and macOS. It covers access probe denial and origin checks, wrong session identity, certificate and IP validation, ignored loopback/private proxy settings, named-process restart, fail-closed configuration, and refusal to retry a potentially executed action. The Linux job also ran the mobile LAN relay tests independently. [Hosted regressions](https://github.com/ui-test-actions/ui-test-actions/actions/runs/44793305328)

The [previous five-platform hour and cancellation report](../v2/lifetime/) remains the duration baseline. This round used short leases, deliberate egress failure and separate cancellation probes to verify the new connection paths.
